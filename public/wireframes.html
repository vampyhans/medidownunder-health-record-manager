MediDownUnder — Low-Fidelity Wireframes

Initial layout reasoning for the registration → consultation notes workflow, before high-fidelity design decisions (colour, type, component styling) were applied.

1 · Login

Wordmark
Email field
Password field
Log in button
Error message area (hidden by default)
Reasoning: single-purpose screen, no nav. Error area reserved below fields rather than a popup, so it doesn't block the form.

2 · App shell (both roles)

Left icon rail nav (role-based items)
Top bar: role badge + name
Main content area
Reasoning: persistent rail keeps role context visible; nav items differ per role rather than one shared menu with hidden items.

3 · Register patient (Receptionist)

Page title
Name
DOB
Contact no.
Address
Inline validation message (per field)
Duplicate-warning banner (conditional)
Save button
Reasoning: two-column field grid for speed; duplicate warning is a banner, not a blocking modal, so receptionist can still decide to proceed.

4 · Search (both roles)

Search input
Results list OR empty state ("No patients found")
Reasoning: one input, no filters, since clinic is small; empty state treated as a first-class screen, not an afterthought.

5 · Patient record (role-conditional)

Patient header (name, DOB, ID)
Receptionist-only: edit demographics button
Clinician-only: consultation history list / empty state
Clinician-only: add note button
Reasoning: same page skeleton for both roles, sections conditionally shown, so the record "feels" like one system rather than two disconnected apps.

6 · Add consultation note (Clinician)

Note text area
Validation message (empty note)
Save note button
Reasoning: single focused field; no rich text, keeps the clinical workflow fast during a consultation.

7 · Audit log

Page title
Chronological log list (who / what / when)
Reasoning: read-only, no actions, deliberately plain since it's a compliance/reference view, not a daily workflow screen.
